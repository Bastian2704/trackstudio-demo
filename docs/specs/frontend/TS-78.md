### 3.4 Riesgo aceptado: cadena `shadcn` → `braces` (decisión del equipo, 2026-10-22)

Quedan **7 avisos altos** sin corrección: `shadcn`, `@shadcn/registry`, `ts-morph`, `@ts-morph/common`, `fast-glob`, `micromatch` y `braces`. `@shadcn/registry` es una dependencia nueva de `shadcn` 4.22.1, a la que `npm audit fix` subió desde 4.15.0 dentro de `^4`, y también depende de `fast-glob`.

- **Por qué no hay corrección:** GHSA-vfj7-8cjw-p6xm afecta a todas las versiones de `braces`, y la última publicada es 3.0.3. Ninguna `shadcn` ≥ 2.0.0 se libra, y por eso `npm` propone bajar a 1.0.0, de 2024.
- **Por qué se acepta:** `shadcn` está en `devDependencies`. Al bundle solo llega `shadcn/tailwind.css`, que es CSS sin JS. La cadena se ejecuta solo cuando alguien del equipo corre el CLI en local, y el peor caso es que ese proceso se cuelgue (DoS).
- **Cuándo se revisa:** cuando `shadcn` publique una versión sin `fast-glob` (el `@ts-morph/common` más reciente ya usa `tinyglobby`) o cuando salga un `braces` corregido.
- **Efecto en Jira:** el AC «`npm audit` sin avisos críticos ni altos» se lee con esta excepción. El ticket tiene que recogerlo (§6).

## 5. Notas de implementación (para el equipo)

Orden de la fase Green:

1. `nvm install 24.22.1 && nvm use` (lee `.nvmrc` después del paso 2). Con `node -v` se confirma.
2. `.nvmrc` → `24.22.1`. `engines` en `frontend/package.json` (§3.1).
3. `tsconfig.node.json` → añadir `"runtime.test.ts"` a `include`. Sin esto, ESLint (`projectService`) rechaza el archivo y `tsc` no lo revisa con los tipos de Node.
4. `npm install axios@^1.20.0 react-router-dom@^7.18.2 vite@^8.1.6 && npm install -D -E vitest@4.1.12`.
5. `npm audit fix` (**sin `--force`**). Revisar el diff del lock: no debe cambiar ninguna mayor.
6. `npm audit`: solo deben quedar los 7 avisos de §3.4. Si aparece otro, se para y se anota.
7. Cadena de calidad: `npm run format:check`, `npm run lint`, `npm test` y `npm run build`.
8. Smoke test en local: login, artistas, producciones y canciones.

**Trampas:**

- `npm ci` con Node 20 solo **avisa** del `engines` (no hay `engine-strict`). El test 1 es el que lo hace cumplir.
- **Conflicto con TS-77:** el PR #48 cambia filas y notas de D2.1. Si se mergea antes, rebasar o mergear `develop` en esta rama antes de editar el ADR.
- Vercel solo respeta la **mayor** de `engines` (24.x) y pone el parche que tenga disponible. El equipo comprueba `node -v` en el log del build de staging.
