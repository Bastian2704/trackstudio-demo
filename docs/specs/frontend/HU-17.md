## 3. Contrato técnico

### 3.1 Dónde vive

Módulo nuevo `src/routes/comments/` (nomenclatura, «`routes/<recurso>/`»), porque HU-18 y HU-19 le añadirán piezas:

- `commentSchema.ts`: tipo `Comment`, esquema Zod del formulario y `formatTimestamp`.
- `commentApi.ts`: `createComment`.
- `CommentForm.tsx` (export default).

`VersionPlayer` guarda una referencia al `<audio>` (`useRef<HTMLAudioElement>(null)`). Si pinta el `<audio>` y el usuario es productor (`useHasRole('productor')`), monta debajo:

```tsx
<CommentForm
  version={version}
  getCurrentTime={() => resumeAt.current ?? audioRef.current?.currentTime ?? 0}
/>
```

- Mientras carga la URL o con un error del reproductor (HU-15 §3.6), **no** hay formulario: sin audio no hay posición.
- **Si la renovación falla mientras se escribe**, el reproductor pasa a error y el formulario se desmonta: se pierden el texto y la marca. El equipo lo acepta (review del PR #68). Para llegar ahí tienen que coincidir tres cosas: la URL caduca, el productor está escribiendo y la renovación falla. Esa renovación falla casi siempre porque la versión ya no existe (404) o porque no hay red, y el guardado fallaría igual.
- Al renovar la URL (HU-15 §3.5) el `<audio>` cambia (`key={dataUpdatedAt}`), pero el formulario sigue montado: lo escrito se conserva. La `ref` apunta siempre al `<audio>` vigente.
- **Posición durante la renovación:** el `<audio>` nuevo empieza en `0` hasta que `onLoadedMetadata` le aplica la posición guardada en `resumeAt` (HU-15 §3.5). Mientras `resumeAt` no es `null`, la posición actual es la guardada, no el `currentTime` del `<audio>`. Si no se hace así, empezar a escribir en ese intervalo toma la marca `0:00` (review del PR #68).
- Sin rutas nuevas: `/canciones/:id/editar` (productor) y `/canciones/:id` (los dos roles) ya montan `VersionHistory` → `VersionPlayer`.

### 3.2 Tipos y funciones

- `Comment`: `{ id: string; version_id: string; author_id: string; body: string; timestamp_ms: number; created_at: string }` (backend §3.6).
- `createComment(versionId: string, input: { body: string; timestamp_ms: number }): Promise<Comment>` → `POST /api/v1/versions/{versionId}/comments` con ese cuerpo exacto, sin más campos. Sale por `api`, con token. Devuelve `data`.
- `commentInputSchema` (Zod): `body` = `z.string().trim()` con mínimo 1 y máximo 2000. Se envía el texto ya recortado.
  - **Cómo se cuentan los 2000:** por punto de código (`[...s].length`), igual que `max:2000` del backend, que usa `mb_strlen`. `.max()` de Zod cuenta unidades UTF-16 y un emoji vale 2: rechazaría textos que el backend acepta (review del PR #68). El mensaje no cambia (§3.3).
- `formatTimestamp(ms: number): string` → `m:ss`, con los segundos truncados y los minutos sin tope: `0` → «0:00», `83500` → «1:23», `59999` → «0:59», `3725000` → «62:05». HU-18 lo reutiliza en la lista y en los marcadores.

### 3.3 Textos

Esta spec es la dueña de los textos nuevos. `{marca}` es `formatTimestamp(timestamp_ms)`.

| Elemento | Texto |
| --- | --- |
| Formulario (`<form aria-label>`) | «Nuevo comentario» |
| Etiqueta del `<textarea>` | «Comentario» |
| Marca tomada (enlazada con `aria-describedby`) | «Marca: {marca}» |
| Botón de envío | «Comentar» |
| Texto vacío o solo espacios (cliente) | «Escribe un comentario.» |
| Más de 2000 caracteres (cliente) | «El comentario no puede superar los 2000 caracteres.» |
| Guardado (`role="status"`) | «Comentario guardado en {marca}.» |
| 422 `errors.body` | El primer mensaje del servidor, bajo el campo |
| 422 `errors.timestamp_ms` | El primer mensaje del servidor, en `ErrorAlert` |
| 422 sin campos conocidos | «Revisa el comentario.» |
| 404 `RESOURCE_NOT_FOUND` | «Esta versión ya no está disponible.» |
| Cualquier otro fallo (500, red, otro `code`) | «No se pudo guardar el comentario. Inténtalo de nuevo.» |

### 3.4 La marca: posición actual al empezar a escribir

1. **Se toma con el primer carácter**, cuando el campo pasa de vacío a tener texto: `timestamp_ms = min(floor(getCurrentTime() × 1000), version.duration_ms)`. Desde ese momento se ve «Marca: {marca}».
2. **Queda fija mientras hay texto**, aunque el audio siga sonando o se mueva la barra: el comentario habla del instante en que se empezó a escribir. Enfocar o salir del campo no la cambia.
3. **Se borra** cuando el campo vuelve a quedar vacío (al borrar todo o tras un guardado correcto). El siguiente primer carácter toma otra.
4. **`floor` y tope:** `floor` nunca redondea hacia arriba. El tope con `duration_ms` evita un 422 si el navegador da una duración unos ms mayor que la medida al subir (`readDurationMs` redondea, HU-13). Si `duration_ms` es `null` (no pasa en una `verificada`, backend §3.5), no hay tope.
5. Al enviar se manda la marca guardada, nunca la posición del momento del envío.

### 3.5 Envío y resultado

- `useMutation` con `createComment`. Mientras se envía, «Comentar» está deshabilitado: un doble clic no crea dos comentarios.
- **201:** se vacía el campo, se borra la marca (§3.4, regla 3) y se muestra «Comentario guardado en {marca}.» con la marca enviada. El foco vuelve al `<textarea>`. No se invalida ninguna consulta: todavía no hay listado (HU-18 lo hará).
- El mensaje de guardado desaparece al empezar a escribir otro comentario.
- Validación del cliente con `zodResolver` (punto 5.4): si falla, no sale ninguna petición. El servidor sigue siendo la fuente de verdad: su 422 se pinta igual (§3.6).

### 3.6 Errores (por `code`, D3.1)

| Situación | Qué se muestra |
| --- | --- |
| 422 `VALIDATION_ERROR` con `errors.body` | Mensaje del servidor bajo el campo, con `aria-invalid` |
| 422 `VALIDATION_ERROR` con `errors.timestamp_ms` | Mensaje del servidor en `ErrorAlert` |
| 422 sin `body` ni `timestamp_ms` | «Revisa el comentario.» |
| 404 `RESOURCE_NOT_FOUND` (versión borrada o no verificada: backend §3.7) | «Esta versión ya no está disponible.» |
| Cualquier otro (500, red, otro `code`) | «No se pudo guardar el comentario. Inténtalo de nuevo.» |
| 401 / 403 | Nada propio: interceptor de HU-04 |

- En todos los errores se conservan el texto y la marca.
- Se ramifica por `error.response.data.code`, nunca por `message` ni por el estado HTTP.
- Un envío nuevo borra el error anterior.

### 3.7 Accesibilidad (RNF-07)

- `<textarea>` nativo con `<Label>` («Comentario») y, cuando hay marca, `aria-describedby` a «Marca: {marca}»: un lector de pantalla oye en qué instante se comenta.
- «Comentar» es un `<Button type="submit">`: se alcanza con Tab y se activa con Enter o Espacio. Enter dentro del `<textarea>` hace salto de línea, no envía.
- Error de campo con `aria-invalid` y texto visible; errores generales en `ErrorAlert` (`role="alert"`); guardado en `role="status"`.
- Esta HU no pinta el texto del comentario. Cuando HU-18 lo haga, será como texto de React (frontend `CLAUDE.md` §4).
