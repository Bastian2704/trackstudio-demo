# HU-06 (frontend) — Listar artistas con estado y producciones

> **Jira:** `TS-17` · **Sprint:** 2 · **Cubre:** RF-01 (listado), RNF-01 (control de acceso)
> **Contraparte:** [`../backend/HU-06.md`](../backend/HU-06.md)
> **Estado:** `[x]` borrador · `[ ]` aprobada · `[ ]` implementada

Los criterios de aceptación de la historia viven en Jira. El contrato de la API (ruta, orden, paginación, forma de `ArtistResource` con `productions` y errores) vive en la spec backend y aquí solo se referencia. Esta spec define la pantalla del listado, sus estados, la paginación en el cliente y la navegación hacia las pantallas de HU-05 y HU-08.

## 1. Alcance en esta capa

**Dentro:**

- Una ruta solo para el productor, `/artistas`, con la tabla de artistas de la página actual: nombre, email, estado y producciones vigentes.
- Paginación con «Anterior» y «Siguiente», guardada en la URL (`?page=N`).
- Estados visibles: cargando, lista vacía, página sin resultados y error.
- Navegación desde cada fila: editar el artista (HU-05), abrir cada producción (HU-08) y registrar una producción nueva para ese artista.
- **Sustituye el apaño temporal de TS-19** (spec frontend HU-08 §1): el alta de producción deja de alcanzarse solo por URL y se llega desde la fila del artista. La ruta anidada `/artistas/:artistId/producciones/nueva` **se conserva**, porque es la que fija el artista sin un selector.

**Fuera / diferido (con motivo):**

- Búsqueda «Buscar artista…» del prototipo → fuera de los AC de TS-17 (backend §1).
- Filtros, orden elegido por el usuario y tamaño de página → los fija el servidor (backend §1). El cliente **no reordena**: pinta en el orden recibido.
- Conteo de producciones «activas» del prototipo → `productions` no tiene estado (backend §1). Se muestra la lista de producciones vigentes.
- Columna de fecha → no se pinta: la zona horaria de presentación sigue **ABIERTA** en D3.2. El orden por fecha lo aplica el servidor igualmente.
- Menú «⋮» de acciones del prototipo → ninguna acción adicional está especificada (cambiar estado es `TS-18`).
- Barra lateral, cabecera y navegación global del prototipo → ninguna HU de S2 la especifica; tampoco se cambia a dónde redirige `Home` al productor (hoy, `/me`). Hasta entonces se llega a `/artistas` por URL o desde los enlaces de HU-05/HU-08 (§3.5).

## 3. Contrato técnico

### 3.1 Ruta

| Ruta        | Página           | Llamada a la API (backend §3.1)              |
| ----------- | ---------------- | -------------------------------------------- |
| `/artistas` | `ArtistListPage` | `GET /api/v1/artists?page=N`                 |

- Se registra en `App.tsx` bajo `RequireAuth` y `RequireRole allowed={['productor']}`, junto a las de artistas. Módulo `src/routes/artists/ArtistListPage.tsx`, export default.
- Un `artista` nunca ve la pantalla: `RequireRole` lo manda a `/403`. Un 403 de la API lo resuelve el interceptor de HU-04.

### 3.2 Página en la URL

- La página actual se lee de `?page` con `useSearchParams`. Un valor ausente, no entero o menor que 1 cuenta como **1** (mismo criterio que el backend, §3.1).
- Siempre se envía `page` explícito a la API: `GET /api/v1/artists?page=1` también para la primera página.
- «Anterior» y «Siguiente» cambian `?page` (entrada nueva en el historial, así que «atrás» del navegador vuelve a la página anterior).

### 3.3 Pantalla y textos

Esta spec es la dueña de los textos de la interfaz de HU-06.

| Elemento                         | Texto                                                                     |
| -------------------------------- | ------------------------------------------------------------------------- |
| Encabezado (`h1`)                | «Artistas»                                                                |
| Enlace de alta                   | «Nuevo artista» → `/artistas/nuevo`                                       |
| Tabla (`<table>`, encabezados `th`) | «Artista», «Contacto», «Producciones», «Estado», «Acciones»            |
| Resumen de paginación            | «Mostrando {from}–{to} de {total} artistas» (de `meta`)                   |
| Botones de paginación            | «Anterior», «Siguiente»                                                   |
| Cargando                         | «Cargando…»                                                               |
| Lista vacía (`meta.total = 0`)   | «Aún no hay artistas registrados.»                                        |
| Página sin resultados (`data` vacía y `meta.total > 0`) | «Esta página no tiene artistas.» y enlace «Ir a la primera página» → `/artistas` |
| Error (`role="alert"`)           | «No se pudo cargar el listado de artistas.»                               |
| Aviso recibido (`role="status"`) | El `notice` del estado de navegación, si llega (`noticeFrom`)             |

**Cada fila** (una por artista, en el orden de la respuesta):

| Columna        | Contenido                                                                                                    |
| -------------- | ------------------------------------------------------------------------------------------------------------ |
| Artista        | `name`                                                                                                       |
| Contacto       | `email`                                                                                                      |
| Producciones   | Lista (`<ul>`) con un enlace por producción: «{name} · {formato}» → `/producciones/{id}/editar`. Sin producciones: «Sin producciones». |
| Estado         | Etiqueta: `activo` → «Activo», `invitado` → «Invitado», `inactivo` → «Inactivo».                             |
| Acciones       | Enlace «Editar» → `/artistas/{id}/editar` y enlace «Nueva producción» → `/artistas/{id}/producciones/nueva`. Ambos con nombre accesible que incluye el artista: `aria-label="Editar {name}"` y `aria-label="Nueva producción para {name}"`. |

- **Formato** con las mismas etiquetas de HU-08 §3.2: `sencillo` → «Sencillo», `ep` → «EP», `album` → «Álbum».
- «Anterior» está deshabilitado en la página 1; «Siguiente», cuando `meta.current_page >= meta.last_page`.
- El resumen y los botones de paginación no se pintan con la lista vacía.
- La tabla, el resumen y los botones no se pintan mientras carga ni con error.
- No se muestran `id` ni fechas. Ningún texto de la API se renderiza con `dangerouslySetInnerHTML`.

### 3.4 Datos (TanStack Query + `api`)

- Función `fetchArtists(page)` en `artistApi.ts`, con `api.get('/api/v1/artists', { params: { page } })`. Devuelve la respuesta completa (`data` y `meta`), no solo `data`: la paginación necesita `meta`.
- Tipos en `artistSchema.ts`: `ArtistProduction` (`id`, `name`, `format`), `ArtistWithProductions` (`Artist` + `productions`) y `ArtistPage` (`data` + el subconjunto de `meta` que se usa: `current_page`, `last_page`, `from`, `to`, `total`). Sin `any`.
- `useQuery` con clave `['artists', 'list', page]`. No colisiona con `['artists', id]` de HU-05.
- `placeholderData: keepPreviousData` **no** se usa: al cambiar de página se muestra «Cargando…» (comportamiento simple y comprobable).
- No hay escrituras en esta HU. Al volver al listado tras crear o editar, la consulta se repite (comportamiento por defecto de TanStack con `staleTime` 0).

### 3.5 Navegación desde HU-05 y HU-08

Para que el listado sea el punto de entrada del flujo, no un callejón sin salida:

- `ArtistCreatePage` y `ArtistEditPage` muestran un enlace «Volver al listado» → `/artistas`.
- `ProductionCreatePage` y `ProductionEditPage` **no cambian** en esta HU: tras borrar ya vuelven a la edición del artista, que ahora enlaza al listado.

### 3.6 Errores (por `code`, D3.1)

| Situación                                  | Qué se muestra                                                                 |
| ------------------------------------------ | ------------------------------------------------------------------------------ |
| Cualquier error de la consulta (500, red)  | «No se pudo cargar el listado de artistas.» en `role="alert"`, sin tabla.      |
| 401 / 403                                  | Nada propio: los resuelve el interceptor de HU-04.                             |

- No hay ramas por `code` propias: el endpoint solo devuelve 401/403 como errores de negocio y los resuelve el interceptor.

## 5. Notas de implementación (para el humano)

- **Reutilizar:** `api` (`src/lib/api.ts`), `noticeFrom` (`src/lib/notice.ts`), `Button` de `components/ui/`, `Link` de `react-router-dom`, `artistSchema.ts` y `artistApi.ts` (se amplían, no se duplican). Las etiquetas de formato ya existen en `ProductionForm`: si se necesitan en dos sitios, extraerlas a `productionSchema.ts` como mapa `formatLabels` (dos usos reales, no especulativo).
- **Orden sugerido de Green:** ruta en `App.tsx` (#15) → tipos y `fetchArtists` → `ArtistListPage` con carga, error y tabla (#1–#3, #12, #13) → producciones y acciones de cada fila (#4–#6) → paginación y URL (#7–#9) → vacío y página sin resultados (#10, #11) → enlaces de vuelta (#14).
- **Página desde la URL:** `Number(searchParams.get('page'))` da `NaN` para `abc` y `0` para ausente; usa `Number.isInteger(n) && n >= 1 ? n : 1`.
- **Botones con enlace:** «Anterior»/«Siguiente» son `Button` que llaman a `setSearchParams({ page: String(n) })`, no `Link`, para que `disabled` funcione de forma nativa.
- **Trampa:** el tipo de la respuesta paginada no es `{ data: T }` como en HU-05/HU-08; `fetchArtists` devuelve `res.data` entero.
- **Trampa de RTL:** las filas de datos se consultan con `getAllByRole('row')` descontando la fila de encabezados, o con `within(tabla).getAllByRole('row').slice(1)`.
