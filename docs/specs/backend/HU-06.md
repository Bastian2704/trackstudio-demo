# HU-06 (backend) — Listar artistas con estado y producciones

> **Jira:** `TS-17` · **Sprint:** 2 · **Cubre:** RF-01 (listado), RNF-01 (control de acceso)
> **Contraparte:** `../frontend/HU-06.md` (pendiente, `ts-06.05`)
> **Estado:** `[x]` borrador · `[x]` aprobada (2026-10-08) · `[x]` implementada (2026-10-08)

Los criterios de aceptación de la historia (listado ordenado por estado y fecha, producciones asociadas por artista) viven en Jira. Esta spec define el contrato backend y los tests que los traducen.

## 1. Alcance en esta capa

**Dentro:**

- `GET /api/v1/artists`: el productor obtiene la página de artistas vigentes, en el orden de §3.3, cada uno con sus producciones vigentes.
- `ArtistPolicy::viewAny`, la acción `index` del controlador y la ampliación de `ArtistResource` con `productions` cuando la relación viene cargada.
- Paginación estándar de Laravel (D3.3) y respuestas D3.1 para 401 y 403.

**Fuera / diferido (con motivo):**

- Búsqueda por nombre («Buscar artista…» del prototipo de Figma, frame `1:373`) → no está en los AC de TS-17. Requiere una HU o una enmienda de Jira.
- Filtros por estado, orden elegido por el cliente y tamaño de página configurable → ningún AC los pide. El orden y el tamaño los fija el servidor.
- Conteo de producciones «activas», como dibuja el prototipo → `productions` no tiene estado (`modelo-sprint-2.md` §5.2). El frontend puede mostrar cuántas producciones vigentes hay a partir de la lista, sin campo adicional.
- Métricas del dashboard y estadísticas del artista → excluidas por el alcance de TS-17 en Jira.
- El caso «el artista ve su propio perfil» de D8.1 → su HU de acceso del artista. Este listado es solo para el productor.
- Rate limiting → D8.5 sigue `ABIERTO`. El contrato es compatible con cualquier salida y no bloquea.

## 3. Contrato técnico

### 3.1 Ruta

| Método y ruta | Middleware | Éxito |
| --- | --- | --- |
| `GET /api/v1/artists` | `auth:auth0-api`, `can:viewAny,App\Models\Artist` | **200** + colección paginada de `ArtistResource` |

- La autorización se declara como middleware `can:` para que la vea el inventario de `ApiRouteProtectionTest`, igual que en HU-05 §3.1.
- Único parámetro de consulta admitido: `page`. Laravel trata un valor no numérico o menor que 1 como la página 1. Una página posterior a la última responde 200 con `data: []` y el `meta` real. Cualquier otro parámetro se ignora.

### 3.2 Autorización — `ArtistPolicy::viewAny`

Permite únicamente `Role::Productor`, leyendo el rol desde `StatelessUserContract` con el `isProducer()` existente.

- Sin token o con token inválido → 401.
- Rol `artista`, o sin rol reconocido → 403. En esta ruta no hay route model binding, así que no existe el caso 404 previo de HU-05.

### 3.3 Consulta y orden

- **Universo:** artistas vigentes (`deleted_at IS NULL`, por el scope de soft delete) en todos los estados, incluido `inactivo`. Hay un único productor (D8.1), por lo que no se filtra por `created_by`.
- **Orden total y determinista**, necesario para que la paginación no repita ni pierda filas:
  1. Estado: `activo` → `invitado` → `inactivo` (decisión del humano del 2026-10-08).
  2. `created_at` descendente: los más recientes primero dentro de cada estado.
  3. `id` descendente como desempate cuando coinciden estado y fecha.
- **Tamaño de página:** 15, el valor por defecto de Laravel. El cliente no lo puede cambiar (§1).
- **Producciones:** se cargan con eager loading en una sola consulta por página. Solo las vigentes (scope de soft delete), ordenadas por `created_at` descendente y `id` descendente. Sin N+1: el número de consultas no depende de cuántos artistas o producciones haya en la página.

### 3.4 Salida

Cada elemento es el `ArtistResource` de HU-05 §3.5, sin cambios, más la clave `productions`. La envoltura `data`/`links`/`meta` es la que produce Laravel al serializar un paginador con `ArtistResource::collection()`.

```json
{
  "data": [
    {
      "id": "9d3c…-uuid",
      "name": "Nombre de catálogo",
      "email": "contacto@ejemplo.test",
      "status": "activo",
      "created_at": "2026-10-05T14:03:11+00:00",
      "updated_at": "2026-10-05T14:03:11+00:00",
      "productions": [
        { "id": "a1b2…-uuid", "name": "Nombre de la producción", "format": "ep" }
      ]
    }
  ],
  "links": { "first": "…?page=1", "last": "…?page=1", "prev": null, "next": null },
  "meta": { "current_page": 1, "from": 1, "last_page": 1, "path": "…", "per_page": 15, "to": 1, "total": 1, "links": [] }
}
```

- Un artista sin producciones trae `productions: []`, nunca `null` ni la clave ausente.
- Cada producción expone **solo** `id`, `name` y `format` (decisión del humano del 2026-10-08). No incluye `artist_id`, que es redundante dentro de su artista, ni fechas.
- `productions` aparece **solo** cuando la relación viene cargada. `POST`, `GET` y `PUT` de un artista individual (HU-05) **no cambian su respuesta**.
- Sin artistas: 200 con `data: []`, `meta.total = 0` y `meta.from`/`meta.to` en `null`.
- Fechas en ISO 8601 con offset (D3.2). Siguen sin exponerse los campos ocultos de HU-05 §3.5.

### 3.5 Errores (D3.1)

Los construye el manejador existente. No se añaden códigos al catálogo.

| Situación | HTTP | `code` |
| --- | --- | --- |
| Sin token o token inválido | 401 | `UNAUTHENTICATED` |
| Rol `artista` (o sin rol) | 403 | `FORBIDDEN` |

## 5. Notas de implementación para el humano

- Orden sugerido de Green: Policy `viewAny` → ruta → `index` del controlador con consulta y orden → `productions` en el Resource → suite completa.
- El orden por estado no es alfabético (`activo` < `inactivo` < `invitado`), así que necesita una expresión explícita, p. ej. `orderByRaw` con un `CASE`. Que los valores salgan de `ArtistStatus`, no de cadenas repetidas a mano.
- Para cargar las producciones con su orden: `with(['productions' => fn ($q) => $q->latest()->orderByDesc('id')])` o equivalente. El scope de soft delete de `Production` filtra las borradas sin código adicional.
- En `ArtistResource`, `whenLoaded('productions', …)` hace que la clave aparezca solo en el listado. Aplicar `select`/`only` a `id`, `name` y `format` en el Resource, no en la consulta: `artist_id` hace falta para que Eloquent asocie las producciones.
- No crear un Service nuevo ni `ArtistService::list()` si la consulta cabe en el controlador sin lógica de negocio; si la consulta crece, va a `ArtistService` (D4.3).
- Cadena de calidad: `sail pint --test` → `sail php vendor/bin/phpstan analyse --memory-limit=2G` → `sail pest`.
- `graphify-out/` no existe todavía; la consulta previa se hizo con lectura dirigida del código vigente.
