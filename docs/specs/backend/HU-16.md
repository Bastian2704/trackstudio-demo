# HU-16 (backend) — Servir audio mediante URLs firmadas

> **Jira:** `TS-27` · **Sprint:** 4 · **Cubre:** RF-04 (reproducción), RNF-02 (confidencialidad del audio), RNF-01 (control de acceso)
> **Contraparte:** — (historia solo de backend). La consume [`../frontend/HU-15.md`](../frontend/HU-15.md) (`TS-26`, pendiente). **Precede:** [`HU-14.md`](HU-14.md) (estado `verificada`)
> **Estado:** `[x]` borrador · `[x]` aprobada (2026-11-04) · `[ ]` implementada

Los criterios de aceptación (ninguna URL pública permanente, expiración obligatoria, URL nueva por sesión) viven en Jira. Esta spec define el contrato backend de la **URL firmada de lectura** (ERD §3.5, ciclo de vida, paso 4) para las versiones `verificada`. La frontera la fijó el equipo el 2026-11-03 (`sprint-04.md`, «Fronteras de alcance»).

## 1. Alcance en esta capa

**Dentro:**

- `GET /api/v1/versions/{version}/playback-url`: devuelve una URL firmada de `GetObject` de 15 minutos (D7.6) para una versión `verificada`, nueva en cada petición.
- `AudioStorageContract::presignDownload()` y su implementación en `S3AudioStorage`.
- Fila RBAC de lectura de `versions` (ADR 8.1): ya existe en D8.1 («Reproducir ✅ desde HU-15/HU-16»). Esta spec la implementa y no cambia el ADR.
- Resuelve la revisión 3 de D7.5: el audio se sirve **directo desde S3 con URL firmada**, no por proxy del backend. El `GET` del CORS del bucket se mantiene.

**Fuera / diferido (con motivo):**

- Reproductor, renovación de la URL caducada y ausencia de enlace de descarga → HU-15 (`TS-26`), frontend.
- Reproducción del artista con acceso vigente → HU-21 (S6): `production_access` sigue vetada (`CLAUDE.md` §5). En S4 el artista recibe 403.
- Proxy del audio por el backend → descartado: haría pasar hasta 500 MB por Railway, en contra de D7.1.
- `Content-Disposition` forzado (`inline`/`attachment`) → no hace falta: el objeto se sube sin esa cabecera y el navegador lo reproduce en línea. Que la interfaz no ofrezca descarga es de HU-15; impedir que alguien guarde lo que ya puede escuchar no es posible con URLs firmadas.
- Bucket privado y Block Public Access → infraestructura de `TS-42` (equipo). Se comprueba en `ts-16.09` y en el test #10 (C4).
- Rate limiting → D8.5 sigue `ABIERTO`; el contrato es compatible con cualquier salida.

## 3. Contrato técnico

### 3.1 Ruta

| Método y ruta | Middleware | Éxito |
| --- | --- | --- |
| `GET /api/v1/versions/{version}/playback-url` | `auth:auth0-api`, `can:play,version` | **200** + URL firmada |

- `whereUuid('version')`.
- Versión inexistente, borrada o con id no UUID → 404 por el route model binding. La cascada de HU-12 borra las versiones con su canción o su producción (`SongService`, `ProductionService`), así que una versión de una canción o producción borrada también da 404, como en la confirmación (HU-14 §3.1).
- Es un `GET`: no cambia nada en el servidor. Cada petición firma una URL nueva.
- Sigue sin existir ninguna ruta `PUT`/`PATCH`/`DELETE` sobre `versions/{version}` (HU-14 #22).

### 3.2 Autorización — `VersionPolicy::play`

- `play(StatelessUserContract $user, Version $version): bool`: solo `Role::Productor`, con el `isProducer()` existente.
- Sin token → 401. `artista` o rol desconocido → 403. El binding resuelve antes que `can:`, igual que en HU-13 §3.2: una versión inexistente da 404 también al artista.
- Fila D8.1 «`versions` · Reproducir»: ✅ productor desde HU-15/HU-16, ❌ artista hasta HU-21. Ya está en el ADR.

### 3.3 Reglas de negocio — `VersionService::presignPlayback`

1. **Solo versiones `verificada`.** Una `pendiente` o una `fallida` responde **404 `RESOURCE_NOT_FOUND`**, con el mismo `detail` que el binding, sin firmar nada (decisión del equipo del 2026-11-04). Fuera del historial una versión sin verificar no existe para quien reproduce (ERD §3.5, paso 4), y así el cliente no distingue entre «no existe» y «no está lista».
2. Pide la firma a `AudioStorageContract::presignDownload($version->s3_key)` y devuelve lo que recibe.
3. **No persiste nada**: ni la URL ni la fecha. No toca `updated_at`.
4. **No hace abandono perezoso.** Una `pendiente` caducada da 404 igual que una reciente. El abandono sigue en la confirmación y en el historial (HU-14 §3.6).

### 3.4 Frontera con S3 — `AudioStorageContract::presignDownload` (D4.3, D7.6)

```php
interface AudioStorageContract
{
    // presignUpload(...) sin cambios (HU-13)

    /** @return array{url: string, expires_at: CarbonImmutable} */
    public function presignDownload(string $key): array;
}
```

`S3AudioStorage::presignDownload`:

- Usa el `S3Client` que ya recibe por constructor (el singleton de `AppServiceProvider`). No construye otro.
- Firma `GetObject` con `['Bucket' => config('filesystems.disks.s3.bucket'), 'Key' => $key]` mediante `createPresignedRequest()`.
- **Expiración:** la misma constante `EXPIRATION_MINUTES` (15) que la subida. Con `$now = CarbonImmutable::now()`: `expires_at = $now + 15 min`, y al SDK se le pasan `$expires_at` y la opción `start_time` = `$now`. Sin `start_time`, el SDK calcula `X-Amz-Expires` con `time()` y puede salir 899, o fallar si el reloj de Carbon está congelado en otra fecha (§5).
- Devuelve `url` = la URI firmada (`(string) $request->getUri()`) y `expires_at`.
- Sin parámetros `ResponseContent*` (§1, «Fuera»).

### 3.5 Respuesta

`200`, cabecera `Cache-Control: no-store, private` (decisión del equipo del 2026-11-04) y cuerpo:

```json
{
  "data": {
    "url": "https://<bucket>.s3.amazonaws.com/<artist_id>/<production_id>/<song_id>/v3.wav?X-Amz-Algorithm=…&X-Amz-Expires=900&X-Amz-Signature=…",
    "expires_at": "2026-11-04T15:20:00+00:00"
  }
}
```

- Exactamente esas dos claves en `data`. No salen por separado `s3_key`, `etag`, `bucket`, `uploaded_by` ni la versión: el cliente ya la tiene del historial (D4.2).
- La URL lleva de forma inevitable el bucket y el key. El key solo contiene UUID (D7.3), así que no expone nombres. La URL caduca a los 15 min (D7.6).
- `expires_at` en ISO 8601 con offset (D3.2). El frontend lo usa para pedir otra antes de que caduque (HU-15).
- `no-store` porque la URL es una credencial temporal: ni el navegador ni un proxy deben guardarla. Laravel envía por defecto `no-cache, private`, que sí permite guardarla.
- Sin `JsonResource`: no hay modelo detrás. El controlador devuelve un `JsonResponse` con `data`.

### 3.6 Errores (D3.1)

No se añaden códigos al catálogo.

| Situación | HTTP | `code` | `detail` |
| --- | --- | --- | --- |
| Sin token o token inválido | 401 | `UNAUTHENTICATED` | (manejador existente) |
| Rol `artista` o desconocido | 403 | `FORBIDDEN` | (manejador existente) |
| Versión inexistente, borrada, id no UUID; canción o producción borradas | 404 | `RESOURCE_NOT_FOUND` | (manejador existente) |
| Versión `pendiente` o `fallida` | 404 | `RESOURCE_NOT_FOUND` | «El recurso solicitado no existe.» (el del manejador existente) |
| Error inesperado al firmar | 500 | `INTERNAL_ERROR` | (manejador existente) |

## 5. Notas de implementación para el equipo

- Orden sugerido de Green: `presignDownload` en el contrato y en `S3AudioStorage` → `VersionPolicy::play` → `VersionService::presignPlayback` → `VersionController::playbackUrl` y la ruta → suite completa.
- La firma con `start_time`: `$this->client->createPresignedRequest($command, $expiresAt, ['start_time' => $now->getTimestamp()])`. Pasar el **mismo** `$now` del que sale `expires_at` hace que `X-Amz-Date` y `X-Amz-Expires` cuadren con lo que devuelve la API, y que el test #8 sea determinista.
- `EXPIRATION_MINUTES` ya es privada en `S3AudioStorage`: la usan las dos firmas. Si cambia D7.6, cambia en un sitio.
- Para el 404 de una versión sin verificar sirve `abort_unless(..., 404)`: lanza `NotFoundHttpException`, que el manejador de `bootstrap/app.php` ya traduce con su `detail`. No hace falta `ApiProblemException` ni repetir el texto.
- La cabecera: `response()->json(['data' => [...]])->header('Cache-Control', 'no-store, private')`. `expires_at` con `toIso8601String()`, como `upload.expires_at` en `VersionController::store`.
- Larastan: anotar `@return array{url: string, expires_at: CarbonImmutable}` en el contrato, la implementación y el Service. La firma `presignDownload(string $key): array` tiene que coincidir con la de los dobles de `tests/Pest.php`.
- Cadena de calidad: `sail pint --test` → `sail php vendor/bin/phpstan analyse --memory-limit=2G` → `sail pest`.
